# Среда

Локальная среда разработки, факты о сборке и приёмы проверок. Правила работы с
боевой базой и S3 — в `CLAUDE.md`; порядок действий — в `docs/process.md`.

Обозначения источника: **по коду** — сверено по клону командой, буквальный
вывод есть в отчёте PR; **со слов Среза 29, 19.09.2026** — утверждение о
машине, проде или внешнем мире, по репозиторию не сверяется.

## Версии

Версии зависимостей не дублируются: единственный источник — `package.json` и
`bun.lock`. Из установленного дерева на 19.09.2026 (по коду): tailwindcss
4.2.4, vaul 1.1.2, `@radix-ui/react-dialog` 1.1.15 (он под vaul), react 19.2.5,
bun локально 1.3.14 — та же версия, что закреплена в CI.

Ключа `browserslist` в `package.json` нет: цели сборки задаёт конфиг
`@lovable.dev/vite-tanstack-config`, их перечень записан в `docs/style-rules.md`
(раздел про `color-mix`).

## Сборка и Tailwind

- Точки перелома — умолчания Tailwind (`lg` = 64rem). `grid-cols-N`
  разворачивается в `repeat(N, minmax(0,1fr))`. Все `lg:*` лежат в одном
  `@media`-блоке после базовых правил; то же верно для `sm:`.
- **Произвольный media-вариант сборка переписывает в range-синтаксис**:
  `[@media(max-height:479px)]:hidden` попадает в CSS как
  `@media (height<=479px){…}`. Искать такое правило в собранном CSS по
  исходному написанию бесполезно — только через `css-extract` по экранированному
  селектору. Целевые браузеры range-синтаксис поддерживают.
- Порядок классов в атрибуте `class` сборка не пересортировывает.
- `src/routeTree.gen.ts` регенерирует `bun run build:dev`.
- `tsconfig.json` включает `scripts/**/*.ts` — скрипты проверяются `typecheck`
  наравне с приложением. CI запускает `bun test` без ограничения корня, поэтому
  тесты в `scripts/` тоже идут.
- `bun run db:generate` — генерация миграции; постхук `postdb:generate`
  вырезает из неё имя схемы.
- Миграций девять, `0000`…`0008`, последняя — `0008_grey_gertrude_yorkes`
  (по коду, `drizzle/`).

## NUL-байты в HTML

В HTML страниц, отданных сервером, встречаются NUL-байты (в снимке страницы
новости прод-сборки — 13; со слов Среза 29, 19.09.2026). Следствие: текстовые
команды по HTML и по собранному CSS запускаются только с `-a`
(`grep -a`, `diff -a`), иначе `grep -o … | wc -l` напечатает «Binary file
matches» и даст 1, а `diff` скажет «binary files differ».

## Локальная база

- PostgreSQL на `localhost:5432`, база `ftspb_local`, схемы `dev` и `public`,
  `DB_SCHEMA=dev`. Боевая строка — только в `PROD_DATABASE_URL` (см.
  `CLAUDE.md`).
- Перед любым `db:migrate` — буквальная проверка, какая схема выбрана:
  `findstr /B DB_SCHEMA .env`.
- Локальная схема `public` отстаёт от `dev`: в `public.news` нет
  `hide_cover_on_page` (со слов Среза 29, 19.09.2026).
- `psql` к локальной базе спрашивает пароль на каждый вызов; кириллица в
  выводе требует `chcp 65001`.

## S3

Бакет `ftspb-media` — один на прод, обе схемы прода и локальную среду. Правила
доступа — в `CLAUDE.md` («S3 не изолирован»), ритуал операции — в
`docs/process.md`. Факты о бакете (со слов Среза 29, 19.09.2026; по
репозиторию не сверяются):

- Бакет публичный на уровне бакета, публичный адрес объекта —
  `https://s3.twcstorage.ru/ftspb-media/КЛЮЧ`, файлы отдаются без Referer.
- У объектов нет `Cache-Control`.
- Multipart-ETag в бакете нет — ETag равен md5 содержимого, на этом держится
  сверка бэкапа перед записью.
- Документы лежат под тем же префиксом `news/`, что и фото
  (`news/СЛАГ/documents/NN.ext` — по коду, `scripts/migrate-archive.ts:323`),
  поэтому любой проход по фото идёт по строкам `news_photo`, а не по префиксу
  S3.

По коду: записывает в бакет единственная функция
`uploadObject(key, body, contentType)` в `src/server/storage.ts` — без ACL, с
явным `Content-Type`; ею пользуются админка и мигратор.

## Снимки и прод-сборка

- Снимок — 71 страница: 60 адресов из карты сайта плюс 11 из `EXTRA_PATHS`
  (по коду, `scripts/ssr-snapshot.ts:43`; среди них
  `/news/nesuschestvuyuschiy-slug-dlya-snimka` с ожидаемым 404).
- Порядок снятия: `bun run build` → копия `.output` в scratchpad → запуск
  сервера из копии с явным портом → снимок по адресу, который сервер напечатал
  в строке `Listening on`. **Снимок базы берётся до создания ветки**: следующий
  `bun run build` перезапишет `.output`.
- Два сервера сборки плюс Chrome упираются в память машины (со слов Среза 29,
  19.09.2026).
- Чужие процессы `node.exe` не трогать: останавливать только свои и только по
  конкретному PID (`taskkill /F /PID`), не по имени образа.
- Dev-сервер поднимается на 8080.

## Windows, Git Bash, prettier

- Репозиторий в LF (`.gitattributes`: `* text=auto eol=lf`).
- Git Bash переписывает аргументы, похожие на пути (`</main>`, `@/…`,
  `/c/…`) — такие аргументы передаются под `MSYS_NO_PATHCONV=1`, а разобранные
  аргументы печатаются, чтобы это было видно.
- `bun` на Windows не принимает MSYS-путь `/c/…` к скрипту: скрипты
  запускаются из PowerShell с Windows-путями.
- Длинное тело PR или сообщение коммита bash не разбирает в heredoc — они
  передаются файлом (`git commit -F ФАЙЛ`, `gh pr create --body-file ФАЙЛ`),
  по-русски.
- Поиск по кириллице — только `git grep`: `findstr` даёт ложно пустой результат
  на UTF-8 из-за кодовой страницы консоли.
- Черновики и отчёты не коммитятся: `.gitignore` закрывает `*.local` и
  `*.local.*` — каталог `batch.local\` (отчёты заданий и образцы) и файлы
  `ИМЯ.local.md` (длинные промпты).
- Артефакты складываются в scratchpad агента, каталоги — короткие: у Windows
  API предел длины пути 260 символов.
- `docs/**` под prettier: ручная вставка строки в таблицу роняет
  `prettier --check`. Файл данных, положенный по заданию, приводится к формату
  `bunx prettier --write`; проверка «изменилась только раскладка» —
  `bunx prettier --stdin-filepath ФАЙЛ < СПЕЦ` и сравнение с файлом.
- `git config merge.ours.driver true` — требование `CLAUDE.md`, ставится один
  раз на клон.
- Пояс машины — UTC+4: `todayInMoscow` (`src/lib/today-msk.ts`) после полуночи
  на час отстаёт от локальной даты машины.
- Файлы планов Claude Code — `%USERPROFILE%\.claude\plans\*.md`, имя по ветке.

## Браузерные проверки

Расширение Chrome. Приёмы, стоившие отдельных итераций:

- **Предусловия замера**: список подключённых браузеров не пуст **и**
  `document.hidden === false`, проверенные в том же вызове, что и замер.
  Вкладка открывается скрытой — её показывает человек. Замер, снятый при
  скрытой вкладке, выбрасывается и переснимается; клики в скрытой вкладке не
  доходят.
- **Ширина** задаётся iframe того же origin (например, на `/robots.txt`;
  origin включает порт), ожидания считаются от фактического `clientWidth`.
  Граница `lg` проверяется на 1100. Скриншот широкого iframe — через
  `transform: scale()`.
- **Загрузку ждать сетевым затишьем**: нет новых записей
  `performance.getEntriesByType('resource')` в течение 1,5 с. Фиксированная
  пауза отказывает ровно на тяжёлых страницах, ради которых пробу писали.
- **Факт загрузки файла** — наличие его URL в
  `performance.getEntriesByType('resource')` окна iframe. Проба ресурсов —
  первое действие в свежем iframe, до кликов.
- **Скрытое отсеивается** по `getClientRects().length`; ждать только конечные
  анимации, таймаут 3 с.
- **Синтетические `TouchEvent`** (`new Touch` + `dispatchEvent`) до React
  доходят, в том числе внутри портала. `.click()` фокус не переводит —
  эмуляция реального клика: `btn.focus(); btn.click()`. Проверять, что клик
  дошёл, — слушателем по `isTrusted`.
- **Узлы диалога запрашиваются заново после каждого открытия**: узлы первого
  экземпляра остаются отсоединёнными (нулевые `rects`).
- **Пробы истории — в верхней вкладке, не в iframe**: у вложенного окна общая
  история. Полная загрузка адреса даёт состояние истории без маркера, одной
  вкладки хватает на все сценарии. Переход `…/slug` → `…/slug#photo=3` — это
  навигация по фрагменту в том же документе, **не** прямой заход; прямой заход
  получается только через уход на другой документ.
- **Скриншот шире окна уменьшается**: размеры и плотность по нему не
  оцениваются — только глазами на машине.
- **Фильтр вывода инструмента JS** блокирует ответ целиком («Cookie/query
  string data»), если в нём есть строки вида `href=/news?page=2` или
  обращение к `sessionStorage`; адрес вкладки при этом не важен. Проба
  возвращает флаги, числа и подписи (`search is page2 true`), без `=` и
  адресов; `async`-обёртка возвращает Promise и печатается как `{}` —
  писать с `await` на верхнем уровне.
- **Кэш прокрутки роутера живёт в `sessionStorage` вкладки** и при уходе со
  страницы дописывается из памяти обратно — `sessionStorage.clear()`
  посреди сессии его не чистит. Контроль «позиция сохранена» при
  `resetScroll: false` снимается с `overflow-anchor: none` на `html`: иначе
  scroll anchoring Chrome двигает окно за переехавшим узлом
  (`docs/lessons.md`).
