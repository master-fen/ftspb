Что лежит в `scripts/` и какие команды есть в `package.json`. Всё сверено по
клону 19.09.2026: список файлов — `git ls-files scripts/`, команды — ключи
`scripts` в `package.json`, коды выхода — по тестам инструментов.

## Проверки

| Команда                   | Что делает                           |
| ------------------------- | ------------------------------------ |
| `bun run lint`            | `eslint .`                           |
| `bun run typecheck`       | `tsc --noEmit`                       |
| `bun run build`           | `vite build`                         |
| `bun run build:dev`       | `vite build --mode development`      |
| `bun test`                | тесты (`bun run test` — то же самое) |
| `bunx prettier --check .` | форматирование                       |
| `bun run format`          | `prettier --write .`                 |
| `bun run charter:check`   | сверка выгрузки Устава с PDF         |

`scripts/` — 162 теста в девяти файлах: `archive-image-rule` 16,

`css-rule-forms` 11, `snapshot-align` 10, `snapshot-compare` 11,

## Инструменты сверки

Лежат в `scripts/`, покрыты `bun test`. Подробные правила применения — в
`docs/style-rules.md`, раздел «Проверка правок оформления».

- **`ssr-snapshot.ts snap БАЗОВЫЙ_URL КАТАЛОГ`** — снимок 71 страницы.
  Отказывает, если каталог не пуст (`:290`).
  **`ssr-snapshot.ts classify КАТАЛОГ_A КАТАЛОГ_B`** — раскладка различий по
  файлам: «совпали», «только манифест», «прочее»; код выхода 1, если «прочее»
  непусто.
- **`snapshot-compare КАТАЛОГ_A КАТАЛОГ_B`** — правка без изменения разметки.
- **`snapshot-align КАТАЛОГ_A КАТАЛОГ_B ОЖИДАНИЕ.json [НАЧАЛО КОНЕЦ]`** —
  правка с изменением разметки: выравнивает страницы, считает изменённые
  `class`, вставки и удаления постранично против ожидания.
- Коды выхода у обоих: **0** — совпало (по ожиданию), **1** — расхождение (в
  том числе файл только на одной стороне; состав каталогов входит в вердикт),
  **2** — ошибка входа или вызова, **включая ноль `.html` на любой стороне**
  («0/0» совпадением не считается). Коды покрыты тестами реальным запуском
  процесса (`snapshot-compare.test.ts:122–158`,
  `snapshot-align.test.ts:152–205`).
- **`snapshot-locate КАТАЛОГ СПЕЦ.json [НАЧАЛО КОНЕЦ]`** — проверяет область
  на всех страницах и находит места по полной строке классов элемента. Код
  выхода 1, если маркер области не найден или есть проблемы.
  `snapshot-locate --expect` сверяет числа плана с фактом и пишет
  `ОЖИДАНИЕ.json` для `snapshot-align`.
- **`css-extract ФАЙЛ.css СЕЛЕКТОР… [LAST:СЕЛЕКТОР] [--объявление…]`** —
  буквальные правила собранного CSS. `LAST:` — селектор последнего правила
  файла, контроль хвоста: извлечение может оборваться молча. Список селекторов
  делится по запятой, но экранированная запятая, запятая в кавычках
  атрибутного селектора и запятая внутри круглых скобок разделителями не
  считаются.
- **`css-rule-forms ВЫБОРКА.txt CSS СПЕЦ.json`** — сверка формы правила
  прежнего класса с объявлениями токена. Спецификация конкретного PR не
  коммитится; инструмент печатает прочитанную спецификацию.

Аргументы с `/` в Git Bash передаются под `MSYS_NO_PATHCONV=1` — см.
`docs/environment.md`.

## Работа с данными

Запускаются человеком; правила доступа к боевой базе и S3 — в `CLAUDE.md`.

- **`bun run db:refresh`** (`scripts/db-refresh.ts`) — `pg_dump` боевой базы по
  `PROD_DATABASE_URL` и разворот в локальную. Отказывается разворачивать в
  удалённую базу (`validate`, `:229`).
- **`bun run db:generate`** — генерация миграции; постхук `postdb:generate`
  запускает `scripts/strip-migration-schema.ts` и приводит `drizzle/meta`
  prettier-ом.
- **`bun run db:migrate`** (`scripts/migrate.ts`) — применение миграций по
  `DB_SCHEMA`. Применяет **все** неприменённые файлы `drizzle/*.sql`.
- **`bun run db:studio`** — drizzle-kit studio.
- **`bun run migrate:archive`** (`scripts/migrate-archive.ts`) — мигратор
  архива легаси, см. `docs/archive-notes.md`. Три режима: по умолчанию —
  поштучно с перезаписью при совпадении слага; `--add-only` — только
  добавить, запись с уже существующим слагом пропускается целиком (ни строки
  в БД, ни объекта в S3); `--replace-all` — полная замена схемы, с
  предохранителем: новости схемы, которых нет в выгрузке, печатаются
  поимённо и режим отказывается работать (обход — `--allow-data-loss`).
  `--add-only` и `--replace-all` несовместимы. Ключ `--skip-uploaded`
  (по умолчанию выключен) перед заливкой файла делает HEAD и пропускает
  объект того же размера; несовпадение размера заливается и считается
  отдельно. `--dry-run` в режимах `--add-only` и `--replace-all`
  подключается к базе и исполняет только SELECT. Остальные ключи —
  `--source=`, `--assets=`, `--schema=dev|public`, `--limit=`.
- **`scripts/parse-archive.ts`** — разбор выгрузки архива. Запускается
  `node`, не `bun` (нужен `TextDecoder` windows-1251). Разбирает 26 годовых
  лент из `archive_pages/` и три смежные ленты вёрстки `media` из `download/`
  (`festvest.html`, `pobeda.html`, `150.html`); идёт двумя проходами —
  разведочный даёт множество страниц, уже ставших телом записи, его счётчики
  сбрасываются. `--profile=ПАПКА` пишет профиль и раздел «Контроли» —
  20 контролей, любой НЕТ — exit 1 после записи файлов. `--self-test` —
  52 кейса на буквальном входе и выходе.
- **`bun run scripts/compress-archive.ts`** — отдельный проход сжатия
  архивных фото до заливки. Читает выгрузку, пишет все фото и документы в
  папку `--out=` с той же структурой каталогов и кладёт туда же
  исправленную копию выгрузки (перекодированный файл меняет расширение).
  Правило — то же, что в админке: GIF не трогается, файл с длинной стороной
  не больше 1600 копируется байт в байт, остальное перекодируется в JPEG 82
  кодером `sharp`. Ключи: `--source=`, `--assets=`, `--out=`,
  `--limit=`, `--concurrency=` (по умолчанию 8). Фазы последовательны:
  существование файлов, метаданные и коллизии выходных имён проверяются до
  первой записи, любая осечка — выход 1. В конце сам проверяет себя: длинная
  сторона каждого выходного изображения, совпадение числа файлов с числом
  путей исправленной выгрузки, существование каждого пути на диске. В S3 и в
  базу не ходит.
- **`scripts/archive-image-rule.ts`** — чистое правило сжатия (зеркало
  `src/lib/image-resize.ts`) и поиск коллизий выходных имён. Покрыт
  `scripts/archive-image-rule.test.ts`.
- **`scripts/archive-migration-rules.ts`** — чистые решения мигратора:
  `created_at` по рангу внутри дня, разделение на вставляемые и
  пропускаемые, предохранитель `--replace-all`, решение о заливке файла,
  разрешение коллизий слагов. Покрыт
  `scripts/archive-migration-rules.test.ts`.
- **`scripts/archive-markers.ts`** — общий модуль парсера и мигратора: форма
  метки `archive-record:ИСТОЧНИК`, её замена на `/news/СЛАГ`, проверка
  остатка. Покрыт `scripts/archive-markers.test.ts`. Импортируется из
  `parse-archive.ts` строго с расширением `.ts` (его запускает `node`).
- **`scripts/dedupe-cover.ts`** — поиск и удаление дублей обложки. Без
  `--dry-run` физически удаляет объекты S3 — при локальной работе запрещено.
- **`scripts/backfill-document-fields.ts`** — дозаполнение полей документов.
- **`scripts/check-content-disposition.ts`** — проверка `Content-Disposition`
  у объектов S3; пишет в боевой бакет.
- **`scripts/text-to-html.ts`** — преобразование текста в HTML.
- **`bun run charter:build`** (`scripts/build-charter-content.ts`) — сборка
  текстового слоя Устава; `--check` (то же, что `bun run charter:check`) —
  сверка без записи.
- **`bun run create-admin` / `bun run delete-admin`** — учётки админки. Имена
  учёток в репозиторий не пишутся. `bun run СКРИПТ` печатает аргументы —
  секреты передаются через `bun run --silent`, переменную окружения или
  интерактивный ввод.

## Не инструменты

- Одноразовые скрипты живут в scratchpad агента, в `scripts/` не кладутся и не
  коммитятся.
- В рабочем клоне в `scripts/` может лежать `library-check.local.ts` — он
  закрыт шаблоном `*.local.*` в `.gitignore`, в репозитории его нет и
  инструментом он не считается.
