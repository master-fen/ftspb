## Долг: архивные фото не сжаты

**7610 архивных фото лежат в бакете как есть** (со слов Среза 29, 19.09.2026).
Причина — по коду 19.09.2026: мигратор читает файл и отдаёт байты в
`uploadObject` без обработки (`scripts/migrate-archive.ts:404–405` для обложки,
`:418` и `:533–538` для галереи). Сайт эти фото не показывает.

Правило сжатия живёт в админке, не в миграторе: `src/lib/image-resize.ts` —
`MAX_DIMENSION = 1600`, `JPEG_QUALITY = 0.82`, сжатие в браузере до отправки;
потребители — `NewsPhotoGallery.tsx` и `PersonPhotoSection.tsx` (по коду
19.09.2026). Мигрированные файлы прошли мимо неё.

При возврате к архиву правило сжатия разумнее встроить в мигратор, чем гонять
отдельный проход. В бакете есть ещё 21 PNG и 28 GIF (со слов Среза 29,
19.09.2026) — для PNG понадобится решение о расширении ключа: сжатие в JPEG
меняет расширение, а ключ уже записан в `news_photo`.

## Сжатие мигрированных фото на месте (18.09.2026, без PR)

Разовая операция: догнать мигрированные фото до правила админки. Выполнена
скриптами вне репозитория, в каталоге операции у Антона; `sharp` 0.35.4,
конвейер `.rotate().toColourspace("srgb").resize(1600,1600,{fit:"inside"}).jpeg({quality:82})`.

Объём — только 144 файла из `dev.news_photo`: затронуто 66, суммарно
285 098 883 → 41 177 123 байт (271,89 → 39,27 МБ); 78 нетронутых сохранили
ETag. Худшая страница (24 фото) похудела со 152 до 8,1 МБ. Среди затронутых —
28 файлов с профилем P3 (цвет одобрен глазами по паре образцов, по пикселям не
мерился) и 2 с EXIF-ориентацией 6. Все 66 есть и в архивном zip. Со слов
Среза 29, 19.09.2026.

Ритуал, по которому это делалось, записан в `docs/process.md` («Операция над
данными в S3»). Сознательно не сделано тем же проходом: второе правило по весу
для трёх файлов 0,84–1,29 МБ, уже укладывающихся в 1600 px; `Cache-Control`;
заполнение `width`/`height`; архивные фото (см. `docs/backlog.md`).

## Долг дублей обложки — закрыт

На легаси-сайте обложек не было, обложкой решили брать первое фото новости.
Мигратор заливал его дважды: `cover.ext` с `position = 0` и `01.ext` с
`position = 1`, под разными ключами.

Лекарство — `scripts/dedupe-cover.ts` (коммиты `bc11651`, `04949e5` от
07.08.2026; оба есть в истории — по коду 19.09.2026). Сравнение пары — по
размеру и ETag объектов (`:241`), удаление — только при совпадении обоих.
Флаги `--dry-run` и `--schema=` (`:37–40`).

Прогон `--schema=dev --dry-run` 17.09.2026: 37 новостей с фото, дублей 0,
осиротевших строк 0; у всех 20 новостей с галереей на `position = 1` стоит
`02.ext` — след удалённого двойника. Схемы прода отдельно не проверялись:
бакет общий, и незавершённый прогон дал бы битые миниатюры. Со слов Среза 29,
19.09.2026.

Под тем же названием жила вторая, другая вещь: ошибка отрисовки плоского
списка фото, из-за которой обложка задваивалась миниатюрой (#41). Она вылечена
раздельными `cover` и `gallery`; запись об этом — в
`docs/history/lovable-coworking.md` (исключение от 07.08.2026).

## Модель обложки

Обложка — картинка карточки новости. Она **не обязана** быть кадром галереи, и
флаг `hide_cover_on_page` нужен как раз для случая, когда показывать её на
самой странице не надо (например, у новости есть видео со своей обложкой). По
коду 19.09.2026: `hideCoverOnPage` — `boolean("hide_cover_on_page")`,
`notNull().default(false)` (`src/db/schema.ts:58`), читается в
`src/server/news.ts:80,166`.
