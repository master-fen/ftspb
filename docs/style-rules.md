# Правила оформления публичной зоны

Целевой вид элементов по ролям. Каждая роль — одно определение в одном месте кода; страницы используют его, не копируют строки классов. Пункты с пометкой «открыто» решаются в PR соответствующей категории и вносятся сюда. Фактическое состояние на момент принятия правил — `docs/style-inventory.md` (снимок `e93831c`).

## Принцип

Вид задаётся ролью элемента, не страницей. Одинаковая роль — одинаковый вид на всех страницах. Новая страница собирается из определений ниже и новых локальных значений не вводит.

## Типографика

Шкала размеров одна — стандартная Tailwind (`text-xs` … `text-4xl`). Произвольные размеры `text-[Npx]` не используются. Исключение — два размера заголовка страницы (28 и 36), взятые из эталона: они оформляются именованными значениями темы `--text-page-title` и `--text-page-title-md` (межстрочный интервал 1.18 задан в них же), не литералами в разметке.

Семейство шрифта заголовков — Manrope (`font-sans`): оно входит в объявление утилит `ui-h1`, `ui-h2`, `ui-h3` и на элементах не ставится (решение Антона, #73). `font-ui` (Inter) — текст и интерфейс; семейство основного текста — открыто до PR по тексту. Подписи (`ui-caption`) семейство не задают и сейчас смешаны (#74): Inter там, где `font-ui` стоит на элементе или предке (строки документов, дата и место на странице события, дата в списке событий, подпись под схемой Структуры, «Редакция от …» Устава, подписи полей руководства), Manrope в остальных; `font-ui` на подписях снимается только вместе с решением о шрифте текста. Заголовок карточки (`ui-card-title`) задаёт Manrope в объявлении, как заголовки страниц и блоков (#75).

Главная страница — единственное исключение: своего заголовка у неё нет, её блоки «Главное» и «Последние новости» — верхний уровень содержимого и оформляются как заголовок страницы (`SectionHeading`: тег h2, утилита `ui-h1` — вид задаёт утилита, тег не меняется). Любая страница, у которой есть свой заголовок, использует для блоков заголовок блока. Других исключений не добавлять.

Скрытый заголовок (`sr-only`, h1 главной) роли не несёт: утилита роли на нём не ставится.

Приглушённый текст — только токен цвета (`text-muted-foreground`). Прозрачность текста (`text-*/NN`) не используется: на разных фонах даёт разный оттенок.

Даты — подпись, цветом не выделяются (синие даты в списке событий убраны в #74). Строка «категория · дата» в карточках списка — подпись; надзаголовок — только строка над заголовком страницы.

Подписи групп бокового меню и «Содержание» в колонке полного текста Устава — подпись (утилита `ui-caption`, тег h2 не меняется), не заголовок блока.

## Ссылки и наведение

Три типа, к одному не сводятся:

- **Текстовая ссылка** (утилита `ui-link`) — при наведении текст становится оранжевым (`brand-orange`), с плавным переходом, без подчёркивания. Ссылки в тексте, подвал, меню, крошки, оглавление Устава, ссылки в карточке руководства. Открыто: ссылки в тексте новости (`.news-prose a:hover`): база оранжевая, наведение navy — конфликт с правилом; решение принимается отдельно.
- **Строка списка** (утилита `ui-link-row`) — при наведении лёгкая оранжевая подложка на всю строку (токен `row-hover`, оранжевый 5%), текст не меняется. Строки документов, записи списка событий, записи будущего календаря турниров.
- **Карточка новости** — своё поведение (подъём, увеличение фото), не меняется.

Кнопки — вне этих правил, у них своё наведение.

Активной ссылка считается по точному совпадению адреса (крошки, ссылки на раздел в подвале). Пункт бокового меню раздела подсвечивается по разделу — на вложенных страницах остаётся активным.

## Крошки

Один компонент. Точки-разделители, приглушённый текст, текущая страница — не ссылка. Ряд переносится на следующую строку при нехватке ширины; фиксированной высоты нет.

## Карточки

Утилита `ui-card`: скругление одно — `rounded-xl`, рамка одна — `ring-1`. Тени нет (решение Антона, #75). Цвет рамки — токен `card-border`, классом `ring-card-border` на элементе (#77). В утилиту он переносится без потерь — проверено сборкой в #77: `@apply rounded-xl ring-1 ring-card-border` дал прежние объявления `ui-card` плюс `--tw-ring-color:var(--card-border)`; перенос — отдельным решением.

Урок #75 уточнён в #77. Источник — сборка #75: `.ui-card` из `@apply rounded-xl shadow-sm ring-1 ring-black/5` получил одну ветку — только `--tw-ring-color:color-mix(…)`, без фолбэка и `@supports`. В Tailwind 4.2.4 это воспроизводится тем же набором. Две ветки (фолбэк и `@supports`) дают одиночные `ring-black/5`, `hover:ring-black/5`, `bg-brand-orange/5`, `hover:bg-brand-orange/5` и пары `ring-1`, `shadow-sm`, `rounded-xl` с `ring-black/5`. Потерю даёт только полный набор; за пределы измеренных наборов вывод не распространяется. `@apply` классов с долей не используется — правило остаётся; после #77 выполняется (`ui-link-row` переведён на `row-hover`).

Карточки роли: «Главное» (`NewsCard`), список новостей (`NewsListCard`), «Последние новости» (`LatestNewsSection`), руководство (`LeadershipCard`). Отступ у карточек роли не единообразен: у `NewsCard` и `NewsListCard` его нет на корне, он лежит на внутреннем блоке; у `LeadershipCard` фото прилегает к рамке, а отступ стоит на текстовой колонке (#81). Плашки пустых списков, панели навигации и оглавления, строки вложений и документов, рамки медиа, подложка логотипа, узел схемы — не карточки.

Открыто: цвет заголовка карточки. Класс цвета снят только там, где буквально тот же класс стоит на ближайшем предке (`NewsListCard`); у «Последних новостей» и руководства (`text-foreground`) он остаётся на заголовке.

Блок «Читайте также» на странице новости — обёртка секции (заголовок секции и список ссылок), не карточка роли; заголовок «Читайте также» — заголовок секции, не роль. Радиус приведён к общему: обёртка оформлена `ui-card` и `ring-card-border` (#81), карточкой роли она от этого не становится.

## Поверхности

Поверхность задаётся ролью элемента, не страницей. Цвет роли — токен темы в `src/styles.css`, в разметке — класс этого токена. Цвета палитры Tailwind (`white`, `black`) токенами темы не являются и в разметке не используются. `style=` с цветом не используется; два таких места в шапке — долг (`docs/ux-ui-problems.md`). `@utility` для фона не вводится: фон — одно свойство, класс токена и есть определение роли.

Доля цвета хранится только в значении токена. Пункты вне ролей (ниже) тоже получают токены: им даётся имя краски, ролью они от этого не становятся.

В классах публичной зоны доли (`/NN`) нет. Текущий способ проверки — поиск ниже. Перечень префиксов в нём неполон по построению: в замере узкий шаблон не находил `from-`, `via-`, `divide-`, `stroke-`, это выяснилось контрольным запросом. При появлении новых цветовых классов перечень дополняется; расхождение поиска и требования решается в пользу требования.

`git grep -n -E "(bg|text|border|ring|divide|outline|from|via|to|fill|stroke|shadow|decoration|placeholder|caret|accent)-[a-z][a-z0-9-]*/[0-9]+" -- src/components/site src/components/federation 'src/routes/_site*' src/routes/__root.tsx src/styles.css`

Инвентарь долей закреплён `tests/style-fractions.test.ts` (тройки «файл, класс, число вхождений»); ручной поиск выше остаётся для диагностики.

Единственное временное исключение — приглушённый текст (`text-*/NN`): долг типографики, записан в `docs/ux-ui-problems.md`, закрывается вне этого этапа. После #81 поиск находит только приглушённый текст и иконки (`text-brand-navy/NN`).

Значение токена с долей — буквально текст ветки `@supports` прежнего класса: `color-mix(in oklab, var(--X) N%, transparent)`, у палитры через `var(--color-black)` / `var(--color-white)`. Сборка Tailwind 4.2.4 раскладывает такое объявление в `:root` на фолбэк и ветку `@supports`, как класс с долей: фолбэк не исчезает, а переносится из класса в `:root` (#77). У токенов на палитре фолбэк — вычисленный hex (`--card-border:#0000000d`), у токенов на переменных проекта — переменная без доли (`--nav-active:var(--brand-blue)`). Худший случай в браузере без `color-mix` — прежний: тот же hex у палитры, сплошной цвет у переменных проекта. Целевые браузеры сборки (chrome 111, firefox 128, safari 16.4, ios_saf 16.4) `color-mix` поддерживают.

Наведение чипа — отдельная роль от наведения строки: значения разные, оранжевый 10% против 5%.

Текст `inverse-foreground` и `inverse-foreground-muted` — на тёмных поверхностях: подвал (`inverse`), фото «Главного» под затемнением (`scrim`), просмотрщик фото (`overlay`). Текст на заливке бренда — кнопки и бейдж вложения на `bg-brand-navy`, активный чип на `chip-active` — `brand-navy-foreground`.

Вне ролей, цвет остаётся на элементе — классом токена-краски, без доли: подложка логотипа (`logo-plate`), skeleton (`skeleton`), бейджи (бейдж формата — `format-badge`), линии схемы и пунктирная рамка узла ревизионной комиссии (`diagram-line`), кнопки (наведение кнопок корневых 404 и ошибки — `primary-hover`), индикаторы (точка крошек — `breadcrumb-dot`), подложка и кнопки просмотрщика фото (`overlay`, `overlay-control`, `overlay-control-hover`).

На элементе остаются: скругление (кроме `ui-card`), отступы, ширина рамки (`ring-1`, `border`), тень, переходы, геометрия в `style=` без цвета. Строка классов роли в другой файл не копируется.

Примитивы `src/components/ui/*` в правило не входят: они читают токены shadcn (`background`, `card`, `popover`, `muted`, `accent`, `primary`, `secondary`, `border`, `input`), и смена значения любого из них меняет примитивы в обеих зонах. `accent` в теме — `muted`, `accent-foreground` — `foreground`: примитивы наводятся на приглушённую поверхность. Именем роли поверхности `accent` по-прежнему не служит.

Тёмная тема не поддерживается: класс `.dark` нигде не ставится, блок `.dark` в `src/styles.css` не расширяется — новые токены пары в нём не получают.

Девятый и последний открытый вопрос закрыт в #84: токен наведения примитивов (`accent`) — нейтральное значение, `muted`. Остальные восемь закрыты в #81: фон карточки сведён к `card-surface`; наведение чипа и наведение строки оставлены двумя ролями (`chip-hover` и `row-hover`); текст на тёмном фоне сведён к двум уровням; флаг рамы главной снят; обёртка «Читайте также» — общий приглушённый фон; у строки вложения фон и рамка — как у строки документа (`muted`, без рамки); разделитель сведён к `border`; фон вокруг медиа разведён — `muted` у фото, `video-backdrop` у видео.

## Контейнеры

`mx-auto max-w-7xl lg:box-content` плюс отступы `px-4 md:px-6 lg:px-10` — контейнер публичной зоны: с `lg` отступы ложатся снаружи `max-width`, на широком экране содержимое 1280 (макет: артборд 1920, поля 320); `w-full` и токены высоты на контейнере не ставятся — при `content-box` они меняют смысл. Сторож — `tests/container-box-content.test.ts`. Шапка держит свои горизонтальные отступы ниже `lg` (#78–#79), с `lg` — те же `px-10`.

Сетка страницы внутри контейнера — `lg:grid lg:grid-cols-12 lg:gap-5` (макет: 12 колонок, межколонник 20); блоки — `lg:col-span-N`. Заголовок над двухколоночной частью — та же сетка на `header` с `lg:gap-x-5`, дети `lg:col-span-8`, чтобы ширина совпадала с текстом по построению, без `calc`. Первый потребитель — `/news/{slug}` (8 + 4). `SectionFrame` (`lg:grid-cols-3`, `lg:gap-6`) — до макета раздела.

## Запрещено

- `text-[Npx]` и другие произвольные значения там, где есть роль из таблицы выше;
- `style=` с цветом;
- `className` из шаблонной строки с переменной или конкатенации — сканер Tailwind таких классов не видит;
- копирование строки классов роли в другой файл — используется общее определение роли.

## Проверка правок оформления

- Поведение сборки доказывает только `bun run build`. Вызов одной библиотеки из конвейера (`optimize` без прохода Tailwind) показал свёртку `color-mix` в `:root`, которой в сборке нет (#77). Проба — временная правка, `bun run build`, буквальные правила собранного CSS, затем `git restore`; одна проба меняет одну ось, иначе результат не приписать причине.
- Проба в DOM собранной страницы разводит гипотезы без пересборки: значение читается и подменяется на живом узле, ось меняется одна, следствие называется заранее. В код вывод переносится отдельной правкой и доказывается уже сборкой.
- Стоп-условие не грубее инструмента метода: `--stat` видит перестановку `preloads` в манифесте, `classify` её отделяет — условие формулируется через `classify`.
- Правка одного CSS меняет хэши всех JS-чанков через граф импортов и переставляет `preloads` — шум каждого PR оформления; состав сборки доказывается листингом чанков.
- Ожидаемые списки страниц записываются до правок, по снимку текущего кода, с числом строк на странице. Сверка с фактом позиционная (страница × строка), не по суммам.
- Списков два. (а) — страницы, где меняется `class` в HTML: доказываются diff'ом снимков и strip-check. (б) — страницы, где вид меняется только через объявление утилиты при том же классе: HTML не меняется, доказываются буквальными правилами собранного CSS до и после. Слитый список не годится: страница из (б) «подтверждается» пустым diff'ом HTML, то есть вхолостую.
- Форма правила каждой новой или изменённой утилиты — селектор, объявления, фолбэк и ветка `@supports` — записывается до сборки и сверяется со сборкой буквально (#77).
- Ассеты сравниваются наборами: порядок записей `preloads` в строке манифеста — шум; состав доказывается листингом чанков (имя без хэша, число файлов, размеры).
- «Различия только в `class`» доказываются опустошением: `classify`; строки манифеста «только порядок» — в сторону; на остальных строках обеих сторон `class="…"` опустошается (кроме `class="$tsr"`); остаток обязан совпасть построчно. Чтение diff глазами — не доказательство.
- У компаратора два контроля через тот же конвейер нормализации: положительный — одна страница дважды, diff пуст; отрицательный — две разные страницы, diff непуст, с числом строк. Нормализация ради шума не расширяется.
- Разбор собранного CSS несёт контроль на хвосте файла: известные правила в конце файла и внутри `@media` обязаны найтись — извлечение может оборваться молча.
- Ожидаемый статус страницы (например, 404 у несуществующей новости) и число тестов после коммита называются заранее; другое значение — стоп, а не поправка ожидания.
- Локатор мест по снимку — по полной строке классов элемента. Места из одного-двух общих токенов — с контекстом (тег, соседний класс, родитель) или в «не покрыто снимками»; ложные совпадения ищутся и исключаются до фиксации списков.
- Когда у двух утилит на одном элементе совпадает свойство или одна читает переменную другой, результат определяет порядок правил в `@layer utilities` собранного CSS — он показывается буквально, рассуждением не заменяется.
- Браузер — для того, чего снимок не видит: размеры, фокус, прокрутка, перемонтирование. Доказательство — идентичность DOM-узла по метке (`dataset.probe`: пропала при перемонтировании, на месте в контроле), а не тайминги.
- `scrollHeight` контейнера включает `::after` и при `overflow: visible`, поэтому равенство `scrollHeight` и `clientHeight` доказательством не является: «не прокручивается» проверяется через `scrollTop` — после попытки прокрутить он остаётся 0.
- Проверка геометрии называет каждое числовое следствие решения, а не одно: снятый зазор сетки даёт и расстояние от фото до текста, и совпадение краёв фото с краями карточки. Проверка исправления запускается до правки и обязана быть красной: зелёная до правки означает, что замер дефекта не видит (#82).
- Успех команды изменения размера окна — не доказательство: ширину подтверждает `innerWidth`, прочитанный после команды. «До» и «после» меряются одним механизмом, иначе сравниваются две разные величины (#82).
- Листинг чанков видит состав и размеры, не содержимое: правка той же длины и ссылка на файл с новым хэшем внутри чанка в листинге невидимы. «Изменилось N чанков» по листингу означает «у N чанков изменился размер», и так это и записывается.
- Пустой вывод у обеих сторон совпадением не считается: перед `cmp` у каждой стороны проверяется итоговая строка с числами. Первый прогон сверки в #83 показал равенство вхолостую — обе стороны упали с «Module not found», потому что `bun` на Windows не принимает MSYS-путь `/c/…` к скрипту.

Инструменты сверки лежат в `scripts/` и покрыты `bun test`. `ssr-snapshot.ts snap|classify` — снимок и разбор различий пары каталогов по файлам. `snapshot-compare КАТАЛОГ_A КАТАЛОГ_B` — правка без изменения разметки: доказывает, что вне строки манифеста каталоги совпали побайтно, манифест совпал после сортировки `preloads`, а `.preloads.txt` совпали. `snapshot-align КАТАЛОГ_A КАТАЛОГ_B ОЖИДАНИЕ.json [НАЧАЛО КОНЕЦ]` — правка с изменением разметки: выравнивает страницы LCS-ом, считает изменённые `class`, вставки и удаления постранично против ожидания и отказывает, если маркер области не найден. `snapshot-locate КАТАЛОГ СПЕЦ.json [НАЧАЛО КОНЕЦ]` — проверяет область на всех страницах (нет начала или нет конца после начала — проблема и код выхода 1) и находит места по полной строке классов: засчитывается атрибут `class`, значение которого точно равно искомому, каждое вхождение отдельно; границы имени атрибута у поиска нет — строка `class="…"` внутри значения другого атрибута тоже засчитается, но разметка React такого не даёт, кавычки в значениях и тексте она экранирует в `&quot;`. `snapshot-locate --expect КАТАЛОГ СПЕЦ.json КАТАЛОГ_ВЫВОДА` сверяет числа плана с фактом по снимку и пишет `ОЖИДАНИЕ.json` для `snapshot-align`; областью он не ограничен и считает по всей странице. `css-extract ФАЙЛ.css СЕЛЕКТОР… [LAST:СЕЛЕКТОР] [--объявление…]` — буквальные правила собранного CSS с контролем на хвосте файла; смещения и хвост считаются в байтах. `css-rule-forms ВЫБОРКА.txt CSS СПЕЦ.json` — сверка формы правила прежнего класса с объявлениями токена. Строки классов и пары «класс → токен» передаются спецификацией JSON, не правкой инструмента; спецификация конкретного PR в репозиторий не коммитится, а инструмент печатает прочитанную спецификацию, чтобы в докладе было видно, что проверялось. Аргументы с `/` в Git Bash передаются под `MSYS_NO_PATHCONV=1`: иначе MSYS перепишет `</main>` в путь, и инструмент получит маркер, которого нет в данных.

Уроки #78–#79:

- `position: fixed` внутри предка с `transform` отсчитывается от предка, а не от окна; вычисленный `top` этого не показывает — мерить `getBoundingClientRect`.
- Ускорение компаратора — изменение метода: жадный срез общих концов ломает выравнивание там, где в данных повторяются блоки. Самопроверка обязана содержать случай формы реальных данных, исправление — отрицательный контроль на прежней версии.
- Проверка, выведенная из предполагаемого механизма, проходит вхолостую (`body` `position: fixed` в vaul — только Safari); механизм подтверждается по исходнику зависимости.
- Правка, снявшая один дефект, может вскрыть второй, который маскировался: до `autoFocus` возврат фокуса «проходил», потому что фокус никуда не уходил, — зелёная проверка при сломанной реализации.
- Проверка называет наблюдаемое следствие, а не факт срабатывания: не «шторка открылась», а «`activeElement` внутри диалога».
