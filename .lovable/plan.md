## Что меняем

Сейчас в разделе `/news` семь чипов-фильтров: «Все», «Главные», «Федерация», «Судьи», «Турниры», «Сборная», «Клубы». По факту в моковых данных живут только две смысловые группы: общие новости и новости категории «Федерация». Остальные чипы обещают контент, которого нет — пустые состояния выглядят как баг.

Оставляем только два чипа и приводим к ним же бейджи на карточках.

## Как организуем фильтрацию

**Модель категорий.** Одна новость — одна категория (`NewsCategory`). На старте только два значения:

- `Общее` — дефолт для любой новости, не привязанной к конкретной коллегии/разделу. Это и есть «общие новости».
- `Федерация` — официальные новости самой Федерации.

Никакого «Все» в самих данных нет — это только состояние UI-фильтра.

**Три UI-чипа, а не два.** «Общее» как категория ≠ «Показать всё». Если оставить два чипа «Все / Федерация», пользователь не сможет отсечь федеральные новости и посмотреть только общие. Поэтому корректный набор:

```text
[ Все ] [ Общее ] [ Федерация ]
```

- «Все» — служебный фильтр UI, показывает всё, активен по умолчанию.
- «Общее» и «Федерация» — реальные категории, один к одному совпадают с бейджами на карточках.

Так фильтр и бейдж говорят на одном языке: клик по «Федерация» = карточки с бейджем «Федерация».

**Бейджи на карточках.** Сейчас показываем `{category} — {date}` для любой категории. Оставляем ту же строку, но значений категории теперь только два: `Общее` или `Федерация`. Никаких «Судьи/Турниры/Сборная/Клубы» в моках.

**Состояние фильтра в URL.** Переносим выбранный фильтр в query-параметр `?category=...` через `validateSearch` + `fallback` (см. tanstack-search-params). Плюсы: ссылка на «Новости → Федерация» шарится, кнопка «назад» возвращает прежний фильтр, SSR отдаёт уже отфильтрованный список. Значения: `all` (дефолт, не пишется в URL благодаря `stripSearchParams`), `general`, `federation`. Русские подписи остаются только в UI.

**Как расширять дальше.** Когда появится реальный контент по судьям/турнирам/сборной/клубам — добавляем значение в `NewsCategory`, добавляем чип, добавляем вариант в схему search-параметров. Правило: чип появляется только тогда, когда в данных есть хотя бы одна новость этой категории. Пустых обещаний в UI не держим.

**«Главные» (`featured`) — отдельная ось.** Это не категория, а флаг «для главной». Убираем из чипов, но сам флаг оставляем в данных — им пользуется главная страница (`FeaturedNewsSection` / «Главные новости»). Смешивать оси «категория» и «главное» в одном ряду чипов не стоит, это разные вопросы к ленте.

## Технические детали

Файлы под правки:

- `src/data/mock.ts` — сузить тип `NewsCategory` до `"Общее" | "Федерация"`; пройтись по моковым записям и переназначить старые категории (`Судьи`, `Турниры`, `Сборная`, `Клубы`) в `Общее` или `Федерация` по смыслу. `featured` не трогаем.
- `src/routes/news.index.tsx`:
  - убрать локальный `useState`, добавить `validateSearch` с `zodValidator` и `fallback` (`category: 'all' | 'general' | 'federation'`, дефолт `all`);
  - `search.middlewares: [stripSearchParams({ category: 'all' })]`, чтобы дефолт не мусорил URL;
  - массив `FILTERS` сократить до трёх пунктов с маппингом на значения search-параметра и русскими подписями;
  - чипы рендерить как `<Link search={{ category: value }}>` с активным состоянием по текущему `Route.useSearch()`;
  - логика фильтрации: `all` → всё, `general` → `category === 'Общее'`, `federation` → `category === 'Федерация'`.
- `src/components/site/NewsCard.tsx` и карточка на `news.index.tsx` — ничего не меняем в разметке, значения бейджа автоматически станут только «Общее» / «Федерация».
- Проверить, что `FeaturedNewsSection`/`LatestNewsSection` на главной не завязаны на удалённые категории (используется только `featured` и сам объект новости — правки не нужны).

Что НЕ трогаем: визуальный стиль чипов, композицию страницы, карточки, детальную страницу новости, футер/хедер.
